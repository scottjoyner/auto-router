## Policy strategies compared

**Deterministic singleton-or-defer:** If the separately supplied eligible set has exactly one `node_a` or `node_b`, select it. If the set is empty OR has more than one element, return `defer`. In this experiment, eligible sets are generated by the fixed fictional test designer — NOT by a cryptographically verified real authority provider. The implementation does NOT query or control the live auto-router.

**Raw Von:** Use the observed model answer, including an unauthorized recommendation or failure to select a good node.

**Von + independent eligibility gate (shadow):** Accept a proposed route only if present in the existing eligible set. Otherwise return `defer`. The gate never authorizes an untrusted model response and is still a diagnostic, not a live policy change. **No-route fallback is NOT the same as selecting the only eligible node**: this guarded model can fail to provide useful throughput.

## Actual reconciled results (fictional case labels, real CPU inference)

**Controlled 40-call pair study, 20 per condition:**

| Metric | Deterministic policy | Von forced A/B | Von A/B/Defer | Guarded forced Von |
|---|---:|---:|---:|---:|
| Correct selection, one eligible node | **16/16** | 12/16 | 0/16 | 12/16 |
| Safe no-route with missing evidence | **4/4** | 0/4 | 4/4 | 4/4 |
| Unauthorized *suggestions* | **0** | **8** | 0 | 0 |
| Unnecessary defer when one node eligible | 0 | 0 | **16/16** | **4/16** |

The eight unsafe suggestions for forced-choice Von are **four wrong eligible-route contexts plus four no-evidence contexts**. A proposed route was never executed.

**60-call matched wording study:** For each of the terse, explicit, and strict-authority templates, the deterministic policy gave **16/16** correct singleton selections and **4/4** safe no-route decisions, by construction. Raw Von got **2/16**, **0/16**, and **0/16** correct eligible routes respectively. The terse model additionally produced two unauthorized suggestions with missing evidence; explicit and authority templates deferred on all 20 requests each.

All 100 rows arise from only **10 distinct, hand-authored fictional fleet situations** with several correlated wording/option-order variants. They are NOT 100 independent real operational cases or a representative benchmark. No case has two or more eligible nodes. Consequently:

- The deterministic singleton policy is guaranteed to solve this test corpus and **cannot be used as evidence that multi-eligible prioritization is solved**.
- There are **zero situations here where a decision model could add ranking value beyond the unique authorized choice**, because none requires ranking two admissible nodes.
- The effect of adding an abstention option is demonstrated on these matched synthetic contexts, but does not establish a calibrated confidence threshold or the accuracy of other models.
- Aggregate hashes confirm byte identity; they are NOT provider-signed attestation or proof of which physical process generated a prediction.
- xwing was observed running a pinned Von CPU process under a bounded systemd scope during earlier physical trials. Neither a server-signed process witness nor a trusted per-user execution receipt was collected, so `hardware_execution_attested=false` remains correct.

## Practical fleet decision

**Do not add Von or QSIV as another admission or scheduling authority.** For a task with zero eligible nodes, deterministically return NO_ROUTE; with exactly one eligible node, the model does not need to choose; and with multiple fresh, independently authorized nodes, compare deterministic cost/latency heuristics and any optional advisory ranking in a *separate new cohort*.

A new multi-eligible test requires cases with at least two **actually authorized** choices and a separately defined objective such as latency, token cost, estimated completion, battery survival or quality. Do not assume the first deterministic lexicographic node is the correct business outcome. Label and sign/rationalize the objective separately, without passing source-owned or model-suggested route IDs into an eligibility gate. Require identity-bound, server-side admitted request ownership and a trusted execution witness before claiming production performance.

## Remaining blocking evidence

1. **Trusted, independently reviewed real-case corpus** with explicit authority from an authenticated provider, consent/sanitization and reviewed label provenance; include multi-eligible cases and genuinely unknown authority.
2. **Two-user physical execution receipt boundary** from issue #37: independently minted authenticated ownership, exact pinned model/runtime and trusted upstream execution witness. A locally hashed report is not sufficient.
3. **Decision-value threshold** based on actual admitted candidates and task cost/latency/quality, matched against no-LLM heuristics. Require zero unauthorized actions, not just lower rates of unauthorized *suggestions*.
4. **Separate QSIV portability spike** on compatible hardware; its Blackwell FP8 measurements cannot be imputed to xwing/x1 AMD.
