# Read-only LFM3 blinded packet/receipt pair-integrity inspection

**Research only; no model inference, external authentication, production access, or permission to use a case set.** This is a narrow recovery aid after private export interruption. The output writer introduced by draft PR #166 creates two private files, but the host can crash between writes. Without independent export-completion evidence, a file's mere existence or a single JSON parse MUST NOT be interpreted as a completed case handoff.

## What this offline audit checks

`python3 -m scripts.lfm3_audit_private_projection_pair --packet /private/notes.json --receipt /private/aliases.json` reads **only** the caller-supplied local packet and custodian receipt and returns a digest/count-only JSON summary. Exit **0** means `PASS_LOCAL_PAIR_LINKAGE_ONLY`; exit **2** means HOLD. It never prints model-facing notes, gold, original case IDs, the private opaque-to-original map or private source dataset digest; no output file is created.

1. Validate each *absolute* path using the existing `lfm3_private_output_writer._target_dirfd`: no symlinked ancestor or final component, only safe system/user directory owners, and a strictly mode-0700 owner-private final parent. Keep the opened parent file descriptor pinned to its exact inode.
2. Read each file via shared `lfm3_private_json_reader.read_private_json` **relative to its pinned parent FD**, rejecting symlinks, hard links, FIFOs, non-owner inputs, group/world-readable modes, missing or zero-byte files, duplicate JSON keys, nonfinite constants, invalid UTF-8 and files changing during read. Hard byte bounds are **2 MiB packet** and **256 KiB receipt**, the same as the exporter.
3. Enforce the **unchanged** original packet and receipt schemas from #162/#163. Packet must have exactly the expected metadata, the pinned expected LFM3 checkpoint, an explicit fictional-only source class and false external custody/inference/production flags. Each of 36–250 cases has exactly an opaque `B` plus 24-hex alias and a bounded, unique note, sorted by alias. The conservative existing obvious gold-hint filter remains in force. No structured gold, challenge tags or original case IDs are permitted in the packet.
4. Receipt must have exactly the expected custodian-only metadata, explicitly false authority claims and an exact canonical SHA-256 binding to the packet. Its case count and one-to-one map of opaque aliases to syntactically valid original IDs must cover **exactly** the packet's aliases. The private source dataset hash is checked for lowercase-hex shape, but cannot be authenticated without the full signed dataset.
5. Return only `case_count` and `blind_prompt_view_sha256` on structural PASS. Every result, including a PASS, explicitly declares `export_transaction_completion_verified=false`, `original_signed_dataset_verified=false`, `external_case_custody_verified=false`, `pre_inference_seal_verified=false`, `actual_model_execution_verified=false`, `model_value_verified=false`, `permitted_to_infer=false`, `production_authorized=false`.

## Recovery behavior and important nonclaims

- **One or both files missing, an interrupted/truncated write, corrupted JSON, changed packet without a correspondingly updated receipt, or unsafe permissions/link path => HOLD.** Preserve the files for a human custodian to inspect; this audit does not delete, overwrite, chmod, repair or regenerate any artifact.
- **Mutually consistent files do NOT prove an atomically completed export**. Two ordinary files can be written before `fsync` and before a power loss; an incomplete transaction might still contain two valid documents. A completed export marker with externally witnessed prior commitment could strengthen this, but is not introduced here, and no retroactive completion is claimed.
- **Both files can be coherently forged** by an adversary who can edit them; the attacker can update the receipt's packet digest and retain internally matching aliases. A dedicated adversarial test deliberately demonstrates a structurally passing forged pair with all trust/authorization flags **false**. Cryptographic signature, independent author ownership and pre-inference source custody require the actual signed full dataset, separately verified human keys, and trusted timestamp from issue #157. Pair linkage must NEVER replace #156's signed-handoff verification or #163's full four-stage reconciliation.
- Existing input reader and output writer do not provide security against a malicious **same-UID** actor who races file changes, nor do they prove trusted filesystem mount, backup policy or custody chronology. The audit relies on Linux `O_PATH|O_NOFOLLOW` and correctly rejects platforms without required safe flags. A final raw path basename is never followed through a different directory after pinning.

## Synthetic acceptance tests

`tests/test_lfm3_private_pair_integrity.py` runs the **real offline packet-export subprocess** to create fresh fabricated fictional cases and ephemeral in-memory signers, then the new **read-only audit subprocess**. It covers normal restricted 0600 packet/receipt success, missing and truncated files, unauthenticated-but-coherent forgery, broken digest, duplicate or missing private alias, forged release flags, gold hint fields, final and parent symlinks, hard links, FIFOs, world-readable data, unsafe parent permissions, oversized otherwise-valid JSON, duplicate keys/nonfinite values, separate private directories and same-path avoidance. The CLI never returns the original ID map, notes or gold in stdout.

This adds no new public input cases or actual model generation, touches none of the frozen #152/#153/#156/#158 scoring/custody/routing contracts, and changes no production path, provider endpoint, credential, signer policy or release gate. All draft PRs remain unmerged; model value, independently sealed new hidden cases, trusted real author/reviewer/witness, GPU attestation and production remain **HOLD**.
