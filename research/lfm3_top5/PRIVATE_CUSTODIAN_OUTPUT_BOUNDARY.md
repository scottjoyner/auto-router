# LFM3 gold-free exporter: owner-private output directory and rollback policy

**Offline research only.** This closes an output-side gap left after the input reader hardening in draft PR #165. The original packet exporter used `O_EXCL` on the destination basename but **followed symlinks in parent directory components**. On a second-write failure it also unlinked the first path by name without checking that the file still referred to the one it created. That is an unsafe cleanup under a concurrently changed directory, even with exclusive creation. The exporter writes a gold-free prompt packet and a separate, confidential **custodian-only alias-map receipt**; the receipt must not be placed in a shared folder or forwarded to the model operator.

`write_private_projection_pair` from `scripts/lfm3_private_output_writer.py` is the single opt-in exporter write path. It creates **no model generation**, network, signing, configuration or production changes. Its protections are:

1. **Absolute canonical output paths.** Reject `.` / `..` components, path collisions and missing/unusable directories. Require safe Linux `O_PATH`, `O_NOFOLLOW`, `O_DIRECTORY` and `O_EXCL`. Rather than a vulnerable `Path.resolve()` path walk, traverse directory ancestors from a pinned `/` FD with `O_PATH|O_DIRECTORY|O_NOFOLLOW`. The resulting handles cannot be redirected through symlinked parent components. The owner of the verified `/` FD is the trusted *namespace system-owner identity*: this supports isolated Linux user namespaces that show host root as a mapped nonzero UID without accepting any arbitrary non-owner UID as trusted.
2. **Private target directories.** The final packet and receipt parent directory must be owned by the executing custodian account and have mode **0700** (no shared access). Ancestors must be owned either by that account or the verified namespace system owner, and must not have group/other write permission except a *system-owned sticky 1777* `/tmp`-style ancestor. Source inputs still follow the separate PR #165 private-file FD reader contract; that reader does not yet walk every input ancestor and operators must separately protect source parent paths.
3. **Pinned directory FD for writes.** A Linux sandbox may deny opening `/` as a readable directory. Ancestor walking therefore uses non-reading `O_PATH` handles. The final verified owner-private directory is reopened *relative to its pinned FD* with `O_RDONLY|O_DIRECTORY|O_NOFOLLOW` and its device/inode identity rechecked. This gives a stable directory FD for `openat` and durable directory `fsync`, without relaxing the no-symlink traversal check.
4. **No overwrites or cross-file aliasing.** Both output locations are opened and checked *before creating the first file*. Existing outputs or same-directory same-filename targets HOLD. Output files are opened exclusively with `O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW`, chmodded `0600`, written, flushed and fsynced. Fixed byte limits are **2 MiB for the model-facing packet** and **256 KiB for the private custodian receipt**. The created directory entries are fsynced after both writes.
5. **Normal-error rollback by identity, not pathname alone.** If a later write or fsync fails, the exporter tracks the first file's `st_dev` and `st_ino`, checks those identities against the current non-followed directory entry, and only unlinks an entry that still points to that *same original regular file*. A replaced inode is left untouched, preventing deletion of a different user's replacement by unsafe cleanup. This is only bounded best effort and deliberately never reports a successful export when a write fails.
6. **Not an atomic transaction across crashes.** Two output files, potentially on different filesystems, cannot be made atomically durable as a single transaction with ordinary `openat`/`fsync`. Power failure, interpreter kill, same-UID attacker or system crash may leave a partial file. **Both packet and receipt always have `permitted_to_infer=false`** and are usable only after external custodian approval. A human must inventory and securely handle any partial files before retrying; the exporter will never overwrite them on rerun.

## Test contract and scope

`tests/test_lfm3_blind_case_intake.py` runs **actual subprocess export** with fictitious temporary signing material for directory modes 0755, 0750, 0770, 0777 and 1777, a symlinked parent, existing receipt, and noncanonical path; all must HOLD without publishing packet/receipt contents. It also tests two distinct owner-private 0700 directories, exact 0600 output modes, fixed output-byte caps, deterministic injected second-write failure (the first file must be rolled back), and simulated replacement of the first inode (the unrelated replacement must **not** be unlinked). Existing normal exporter, all PR #165 private *input* source protections, frozen #152 scorer, #153 repeatability, #156 signatures, #158 primary selector and #162/#163 blind schemas remain unchanged.

A test PASS means the **fictional local exporter file boundary** behaves as described. It is not evidence of independently verified author/reviewer/witness identities, independent TSA/corpus sealing before inference, real model-value evidence, live model generation, SGNC custody, or approval of a release.
